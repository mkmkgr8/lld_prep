# PDF Errata: Spoilers. Attempt `drill pdf-bugs` first.

Page numbers refer to `LLD_Complete_Reference.pdf` (C) and `LLD_Deep_Reference.pdf` (D).

| # | Where | Bug | Severity | Fix |
|---|---|---|---|---|
| 1 | C p15, **Thread-safe LRU** | `LinkedHashMap(..., accessOrder=true)` **reorders its linked list on `get()`**, so `get` is a write. Guarding it with a *read* lock lets concurrent gets corrupt the list. | BLOCKER | Use an exclusive lock for `get` too (or a plain `synchronized`). If read-heavy, use a segmented/striped cache or accept approximate LRU. |
| 2 | C p20 / D p25, **ParkingLot.park** | `findAvailable()` then `spot.park()` is check-then-act across two separate locks. Two gates can pick the same spot, and the loser gets `IllegalStateException` even though other spots are free. | MAJOR | Make occupy a single atomic op (`tryOccupy` with CAS, returning boolean) and **retry the next candidate** on failure. See `solutions/_reference/parking-lot`. |
| 3 | C p20 / D p25, **Singleton getInstance(floors, pricing)** | Args are silently ignored after the first call. It's also untestable, because tests can't get a fresh lot. | MAJOR | No Singleton. Construct once in `Main` and inject it. |
| 4 | C p21 / D p28, **TokenBucket `synchronized tryAcquire`** | Correct, but it's one lock for **all** clients, so every request serialises. The PDF calls it "thread safe per client", which is wrong. | MAJOR (at SDE-3) | `buckets.compute(clientId, (k, b) -> refillAndTake(b))` for an atomic per-key update, or a per-bucket lock. |
| 5 | C p10 / D p17, **EventBus.unsubscribe** | `getOrDefault(event, List.of()).remove(o)`: `List.of()` is immutable, so `remove` **throws `UnsupportedOperationException`** for an unknown event. The map and lists aren't thread-safe either. | MAJOR | `Optional.ofNullable(listeners.get(e)).ifPresent(l -> l.remove(o))`. Use `ConcurrentHashMap` + `CopyOnWriteArrayList`. |
| 6 | C p25 / D p35, **Splitwise settle** | `Double.parseDouble(userId)` crashes on non-numeric IDs (e.g. UUIDs). It also uses `double` for money. | MAJOR | Keep `record Balance(String userId, long paise)` in the heaps. |
| 7 | C p24 / D p32, **Split hierarchy** | `calculateAmount()` mutates `amount` and is called inside the `Expense` constructor, so the object is half-initialised until then. `EqualSplit` has a rounding remainder (100/3), and nobody gets the extra paisa. | MINOR | Make the split strategy a pure function that returns `Map<User, Money>`, and assign the remainder to the payer or the first user. |
| 8 | C p43–44, **Library.checkout** | Filters by `status==AVAILABLE`, then `checkout()` may lose a race and return `false`, even though another copy is free. `memberId` is unused, so nobody tracks who borrowed. The fine is hardcoded to `MemberType.PUBLIC`. | MAJOR | Try each available copy until one succeeds. Add a `Loan(member, copy, due)` entity and look up the member's type. |
| 9 | C p9 / D p15, **CachingProxy** | Not thread-safe: `cache` and `cacheTime` race, and it uses `System.currentTimeMillis()` directly. | MINOR | `volatile` holder of an immutable `(value, time)` snapshot, plus an injected `Clock`. |
| 10 | C p30 / D p44, **Seat reservation** | Uses `LocalDateTime.now()`, so expiry can't be tested. An expired hold is only reclaimed lazily when someone else tries to reserve, so `getAvailableSeats()` under-reports availability. | MINOR | Inject `Clock`. Treat expired `RESERVED` as available in reads, or run a scheduled sweeper. |
| 11 | C p32 / D p48, **confirmBooking** | `allMatch` short-circuits. If seat 2 fails, seat 1 is already `BOOKED`, and then `expire()` releases seat 1 even though it was confirmed. | MAJOR | Validate every seat under ordered locks first, then flip all of them to `BOOKED`. Or move the booking to a `BookingStatus` state machine with a single CAS. |
| 12 | C p40, **ATM** | `ATM` state fields aren't thread-safe. That's fine if the ATM has one physical user, but say so. `(int) amount` truncates. There's no denomination handling, so it misses the Chain of Responsibility that the classic ATM question expects. | MINOR | State the single-user assumption. Use `long` paise. Add a `2000→500→100` dispenser chain. |
| 13 | C p28, **Elevator** | `ElevatorRequest` direction is ignored when adding to the up/down sets, and `step()` teleports to the next floor. This is acceptable as a sketch, but interviewers ask "what about a request *behind* the elevator going the same direction?" | MINOR | Know the LOOK vs SCAN answer, and keep a pending set for requests that come in behind. |
